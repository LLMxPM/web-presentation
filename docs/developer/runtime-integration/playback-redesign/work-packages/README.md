状态：**A1/A2/B0–B5 工程已完成，C1–C3 待实施，D1–D3 推迟**。完成记录见[开发记录](../development-record.md)。本清单执行[放映动画能力收敛规划](../../playback-redesign-proposal.md)；放映优先，永久放弃任意时刻状态重建，无历史发布数据，不安排旧接口兼容、存量页面迁移或双版本混跑。工作包编号与旧 motion/slideshow/audio/threejs 的编号无关。

取代 2026-10-23 的 WP01–WP16 十六包草案。2026-10-29 调整为先核对现状与验收设计（A 段），再实施替换（B 段），最后工程收口并集中实机验收（C 段）。A1/A2 不再要求旧实现的实机贯通与支持矩阵实测；相关任务全部由 C3 对最终实现执行。**不新建第二套播放内核，不推倒重做。**

## 完成记录和验证

状态使用“待实施 → 实施中 → 待验收 → 完成”。A/B/C1/C2 的“完成”仅代表该包工程交付与开发测试通过，不代表产品已通过实机验收；尚待 C3 的项目逐项列出。C3 完成后才可宣布 GC 通过。每张卡片回填代码版本、实际命令、通过/失败数量、未运行项和接手条件；浏览器与产物证据统一在 C3 登记。按[dev-start-test](../../../../../.agents/skills/dev-start-test/SKILL.md)选择最小充分测试；需要服务时先探测复用。

直接替换期间 dev 允许全量门禁不绿：逐包运行单测、无浏览器集成测试、类型检查、契约与生成门禁，记录尚待调用端替换的已知红项；B0/B1/B2 的默认截图、导出接线与对应开发回归不得作为已知红项拖到 C3。真实浏览器、Renderer、镜像与产物测试可以尚未运行，但不得记为通过。全量主门禁与相关专项门禁统一在 C3 收口；失败回修后重验受影响场景，并重新确认最终源码、镜像与产物身份。中间态不补兼容层或运行时 fallback。

新增源码遵守根仓中文注释与文件头要求；Editor UI 遵守 `DESIGN.md`。HTTP DTO 改动须生成 Editor API 类型并通过生成契约门禁，RenderContracts 的 Python DTO 与 JSON Schema 必须对拍。Runtime Kit 的新公开路径须带 `.vN` 并进入 manifest。跨仓 CLI 在其仓库提交与验证，本仓只维护 External API 契约和对接记录；MCP 不在交付链，但 External API 变化会使其契约快照失配，按 B5 记录为非阻塞。
