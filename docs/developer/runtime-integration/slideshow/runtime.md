# Runtime 翻页动画与自动放映实施计划

状态：M0 已实现（WP11、WP12：动画参数解析、过渡完成信号与真实 Chromium 验收）；WP13–WP18 已交付调度状态机、执行上下文、Router/就绪桥接、单窗口控制、静态捕获与导出隔离（2026-10-17）；WP22 交付媒体 Schema 与预览权限链、WP23 交付活动页媒体注册与生命周期适配层、WP24 交付媒体结束翻页与受阻恢复、WP25 交付演讲者同步协议 v2（2026-10-18）。双屏调度与能力开放待实施。配置由 Backend 提供，字段和覆盖语义以[统一契约](./contract.md)为准。

实施拆分见[工作包执行清单](./work-packages/README.md)：WP11 动画与信号、WP13–WP16 调度及上下文、WP23–WP26 媒体与双屏、WP31–WP33 长期运行。以下 R 编号保留为上层职责。

## 2. 工作包

### R01：参数解析与动画完成信号（M0，依赖 B03）

- [x] 消费 Backend 路由产物中的项目默认和叶子生效配置；保留旧产物缺字段时的手动行为和现有过渡兜底。
- [x] 将宿主 `settled` 和渲染错误向上接通，信号携带路径与本次页面 generation，避免旧页完成事件启动新页计时。
- [x] 动画以目标层的过渡完成事件为主要收尾条件，保留有界计时兜底；过滤子元素冒泡事件，无动画/减少动态效果也必须恰好完成一次。
- [x] 明确 `settled` 只表示整页过渡完成，不能替代页面 DOM/资源就绪；初次无动画挂载需在 DOM 提交后报告稳定页。
- [x] 当前页选择器排除离场层和缩略图，保留最多两层、反向推入、快速导航合并和失败恢复。

验收：默认与逐页动画在普通模式、观众窗口和构建产物一致；连续导航不重复完成、不残留旧媒体。

### R02：单窗口调度器（M1，依赖 R01）

- [x] 将控制器绑定到 Router 会话而非页面组件，统一持有播放状态、当前路径、generation、剩余时间和计时句柄。
- [x] 实现 `stopped`、`preparing`、`playing`、`paused`、`ended`、`blocked`、`error` 状态及明确的状态迁移；M1 不开放媒体模式。
- [x] 等待“当前路由提交＋页面 DOM/必要视觉资源就绪＋过渡完成”后开始停留计时；资源失败保留可见错误并暂停，不无限等待。
- [x] 复用现有导航目录和 `navigateRuntimePage`；只推进可见叶子页，隐藏页和分组不参与自动序列。
- [x] 用单调时钟计算本窗口剩余时间，使用可取消的一次性调度，避免固定 interval 与导航耗时叠加。
- [x] 手动跳页作废旧计时；播放中从新页重计时，暂停中保持暂停；停止保留当前页，重新开始从当前页计时。
- [x] 手动模式页面等待用户操作；末页完成后按项目设置停止或循环，单页循环同样有完整停留周期。
- [x] 普通窗口隐藏时暂停并保留剩余时间，重新可见后等待显式继续；回前台不连跳补课。自动开始只在本次宿主初始化时尝试一次。

WP13 交付与 Router/DOM 解耦的控制器，WP15 完成 Router 会话绑定、就绪桥接与导航目录接线，WP16 完成可见性暂停、控制条与一次性自动开始入口；上述已勾选项由虚拟时钟、宿主集成与真实浏览器用例覆盖。完整手动连跳与阶段能力开放在 WP21。

验收：暂停/继续不丢剩余时间，过渡和加载不吃停留时间，任何旧回调都不能重复翻页。

### R03：执行上下文与操作区（M1，依赖 R02，向 G01 提供上下文契约）

- [x] 引入内部执行上下文，区分放映主画布、单页交互预览、缩略图、捕获和导出；嵌入式普通单页预览优先采用禁自动策略。
- [x] 缩略图、控制台当前/下一页小窗、卡片页、资源/组件预览禁止自动媒体播放；`inert` 只阻止交互，不能作为禁播实现。
- [x] 捕获和导出强制禁用自动开始、翻页及媒体播放；执行上下文优先级高于项目和页面配置。
- [x] 普通放映提供开始、暂停、继续、停止、剩余时间/页码与状态文字；保留现有导航快捷键，避免空格同时触发两个动作。
- [x] 暂停放映同时暂停本会话媒体；只恢复此前正在播放的媒体，不启动用户手动暂停的媒体。
- [ ] 不把 Runtime shell 控制器、缩略图或 presenter 内部能力放入公开 Runtime Kit manifest。

WP14 已交付上下文解析、宿主传播、媒体禁播守卫与暂停/恢复协调器；WP16 已接入控制条、空格快捷键、可见性/模式清理与当前页媒体暂停/恢复，真实浏览器验证 1440/1180/960px 入口与全屏空格不双触发。WP17 已让 Renderer 捕获导航固定 `runtimeCapture=1`，并在 render-ready 桥中上报执行上下文与目标路由，真实 PNG 覆盖 poster 与无 poster 视频。WP18 已让 PDF、PPTX 与打印全部使用 `capture` 上下文的离屏舞台，捕获标记同时进入 search/hash，真实产物验证导出期间主画布暂停状态、页码与剩余时间不变。媒体结束与双屏仍属 M2。

验收：自动放映期间缩略图不抢播、捕获不跳页，卸载/模式切换清理计时和监听器。

### R04：媒体生命周期与结束翻页（M2，依赖 B06 的 Schema/权限适配及 R03）

- [x] 当前活动画布内统一收集非循环原生音视频作为完成目标；`media_end` 主动播放并等待全部结束，没有目标时走停留时间。
- [x] `VideoViewer` 转发播放、暂停、结束和错误状态，提供可控实例或内部注册；原生 HTML 媒体采用相同规则。媒体事件在实际元素上监听或显式转发，不能依赖 `ended` 冒泡。
- [x] 目标页过渡前暂缓媒体启动，过渡完成后按模式执行；离场、取消、页面错误和卸载均停播并移除监听。
- [x] 处理 `play()` Promise 拒绝，进入 `blocked` 提供点击开始；`error`、断网和 `media_timeout_ms` 到期进入错误暂停，提供重试、下一页、停止。
- [x] 区分媒体停止、播放结束和循环；对多媒体、动态新增/移除、视频替换及迟到事件维护同页 generation 内的一次完成集合。
- [ ] 自动播放默认不能推断为成功；真实播放状态来自 Promise 和事件，兼容有声、静音与移动端行内播放。

本期受控范围是当前画布内的原生音视频及 `AssetVideo`。第三方 iframe 播放器、Web Audio、自定义脚本在画布外创建的音频和任意页面内部定时动画不纳入统一暂停/结束判定承诺；需要适配时单独增加版本化能力与验收，不能用 DOM 扫描宣称已覆盖。

WP23 已交付 `page-media-session`：活动页根节点内的非循环音视频在实际元素监听，动态增删与替换会刷新集合，事件按页 generation 隔离；`play()` 区分阻止与错误，暂停/恢复只处理本会话记录的目标，销毁时停播并移除监听。`VideoViewer` 已转发原生事件并暴露受控元素，未向公开 Runtime Kit 增加新能力。`media_end` 何时启动、超时与受阻恢复的调度在 WP24 接入。

WP24 已把媒体会话接入调度：就绪后按 `media_end` 播放并等待完成集合，无媒体或动态清空退回停留时间；超时、失败进入错误暂停，策略阻止进入受阻态，控制条提供重试、下一页和停止。暂停保留媒体时限并只恢复本会话停播的目标，循环背景不参与完成但随暂停/销毁停播；单页循环会重建会话重播。真实 Chromium 覆盖多视频结束推进、暂停进度、失效资源、超时与恢复；有声素材与移动端行内播放留待 WP30。

验收：单/多视频、无视频、循环背景、播放被阻止和中途跳页均按[契约](./contract.md)执行。浏览器行为参见 [Chrome autoplay 说明](https://developer.chrome.com/blog/autoplay/)和 [MDN ended 事件](https://developer.mozilla.org/en-US/docs/Web/API/HTMLMediaElement/ended_event)。

### R05：演讲者双窗口（M2，依赖 R04）

- [ ] 普通单窗口由当前窗口调度；双窗口由观众窗口唯一调度，控制台只发命令并显示状态，不运行第二个推进定时器。
- [x] 扩展现有 BroadcastChannel/localStorage 兜底消息，携带协议版本、频道/产物身份、owner epoch、命令 ID、递增 revision、当前路径、状态和剩余毫秒。
- [x] 新窗口 ready 后发送状态快照，重建本地时钟基准；不跨窗口直接比较 `performance.now()`，重复和过期消息必须去重。
- [ ] 进入/退出演讲模式先暂停，再交接状态；调度权交接必须先失效旧 owner。观众窗口未就绪或关闭时控制台保持暂停，重新打开需显式继续。
- [ ] 控制台隐藏不暂停仍可见的观众窗口；观众窗口隐藏/失去可执行条件时暂停。不能只依据控制台 `visibilitychange` 控制观众。
- [ ] 全屏退出本身不重置播放进度；现有演讲计时面板继续表示演讲用时，与放映剩余时间分开。
- [ ] 控制台手动跳页、观众键盘导航和恢复都经过统一控制器，避免消息回声与双重计时。

WP25 已交付协议 v2 与纯处理器：信封携带频道/产物身份、owner epoch、revision、命令 ID 和完整播放快照；接收端在应用前拒绝旧版本、身份不匹配、重复、旧 revision 与旧 owner，并用本地到达时间重建 deadline。控制器的 `playbackSnapshot`/`remotePlayback` 已暴露给 WP26，但调度权、可见性暂停与交接仍待 WP26。

验收：控制台与观众状态一致、只有一次自动翻页，关闭重开和重复消息不会抢占或恢复旧播放。

### R06：本地构建产物长稳（M3，独立验证）

- [ ] 定义本地放映入口：通过普通用户鉴权下载不可变构建产物 ZIP，按产物 base 在本地静态服务放映；远端构建访问入口、构建访问票据/按构建 Cookie 和代理不属于 M3，由独立代理服务另行设计验收。
- [ ] 验证本地服务中断、浏览器重载/崩溃后的显式恢复和失败提示，不引入无限重试或自动修改快照。
- [ ] 在目标浏览器验证防休眠与退出清理，权限被拒时回退为普通放映；不默认申请或承诺所有设备可用。
- [ ] 完成多轮循环的媒体句柄、内存和监听器长稳验证；验收通过前不宣传全天无人值守或产品级远端放映。

## 3. 验证安排

纯控制器用虚拟时钟覆盖计时、暂停、作废回调、循环和状态迁移；挂载测试覆盖动画信号、上下文传播及媒体清理。真实浏览器验收动画、视频、权限、双窗口和缩放，不能仅依赖 JSDOM。具体场景、阶段门槛和证据见[验收计划](./acceptance.md)。
