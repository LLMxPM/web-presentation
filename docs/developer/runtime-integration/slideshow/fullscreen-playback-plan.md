# 全屏放映统一模型与实施规划

状态：已实施（2026-10-18）
范围：Runtime 项目放映、演讲者模式、Editor 放映入口与相关文档
上位计划：[翻页动画与自动放映实施总计划](./README.md)
相关模块：[Runtime 计划](./runtime.md)、[Editor 计划](./editor.md)、[联调与验收计划](./acceptance.md)

本规划是 M3 完成后的交互收敛，不新增 Backend 字段、External API 或预览构建契约。目标是把已经存在的放映控制器、全屏布局和演讲者双窗口收敛为一条状态链；实施时更新现行文档和回归证据，不回溯改写已完成工作包的历史记录。

## 1. 背景与问题

自动放映、全屏预览和演讲者模式此前分别演进，Runtime 中同时存在两套翻页入口和两套快捷键：

- [PlaybackHostBridge.vue](../../../../runtime/src/runtime-shell/playback/PlaybackHostBridge.vue) 无条件挂在 [ResponsiveLayout.vue](../../../../runtime/src/runtime-shell/layouts/ResponsiveLayout.vue) 中。只要产物带 `playback` 配置，控制器就会创建，`stopped` 状态也会渲染底部控制条。
- 全屏只是布局内的局部状态，和播放状态互不相干：可以“放映但未全屏”，也可以“全屏但未放映”；退出全屏不会停止自动推进。
- 旧的右上角翻页、底部缩略图、画布两侧箭头与新的控制器自动翻页同时存在；手动翻页会隐式重置停留计时。
- 空格键存在多种含义：预览层按旧逻辑翻页，播放层在捕获阶段切换开始/暂停，演讲者控制台又是下一页。
- 演讲者控制台同时存在放映面板、演讲计时和旧的上一页/下一页；观众窗口还会自己响应键盘。
- Editor 入口只有“放映”，但打开的是旧整项目预览壳；用户无法区分“预览”和“放映”。

这些问题不是缺少功能，而是缺少统一的归属：谁拥有页面推进、谁决定全屏、谁决定自动或手动。

## 2. 目标与非目标

### 2.1 目标

- 明确 **非全屏 = 预览，全屏 = 放映**；退出全屏就是结束本次放映。
- 复用现有 `PlaybackController`，不重写调度、媒体和转场就绪链路。
- `auto_start` 只决定进入全屏时的初始模式；运行中可以在自动和手动之间切换。
- 手动模式只停止页面自动推进，不暂停正在播放的媒体。
- 全屏放映只保留一条控制条和一套键盘语义，预览态不再出现放映控制条。
- 演讲者模式收敛为“观众窗口是放映本体，主窗口是控制台”，不产生第二个调度器。
- 不新增 `runtimeMode`、不新增播放布局、不改变 Backend 存储结构。

### 2.2 非目标

- 不重新设计 `none/fade/push` 转场、媒体判定或截图/导出隔离。
- 不新增远程控制、移动端适配、Firefox/WebKit 验收或无人值守代理。
- 不保留“带侧栏/缩略图的全屏预览”；全屏即放映，需要目录时退出到预览。浏览器级 `F11` 全屏不在此模型内且无法被页面拦截，此时仍是预览。
- 不新增 Backend 字段；`auto_start` 只调整运行语义和界面文案。
- 不改变页面内容、组件、主题、资源或构建产物格式。

## 3. 核心模型

### 3.1 三个场景

| 场景 | 触发 | 播放控制器 | 界面 |
| :--- | :--- | :--- | :--- |
| 预览 | 非全屏项目壳 | 不创建 | 侧栏、缩略图、卡片、导出、旧的上一页/下一页 |
| 放映 | 根元素进入全屏 | 创建并启动 | 纯画布 + 一条放映控制条 |
| 演讲 | 放映中点击“演讲” | 观众窗口唯一持有 | 主窗口控制台 + 观众窗口全屏放映 |

Editor 页面详情的“放大查看”仍是单页 iframe 弹窗，不属于本模型；它没有路由、整页转场和放映控制。

### 3.2 全屏即放映

- 进入全屏时创建本次放映的控制器并启动会话，不提供单独的“开始”按钮。
- `auto_start=true` 表示进入后默认自动推进；`auto_start=false` 表示进入后默认手动，页面可翻但不会自动前进。
- 退出全屏时停止计时、媒体并销毁控制器，回到预览；当前页保持不变。
- 全屏请求被拒绝时留在预览并给出可见错误，不静默降级为窗口放映。
- 只有 `document.fullscreenElement === document.documentElement` 才视为放映全屏。视频、图表等页面内元素全屏期间 `fullscreenElement` 不是根元素，放映状态保持不变：继续按当前模式推进，也不暂停媒体。
- 退出页面内元素全屏后，Chromium 不会恢复根元素全屏，`fullscreenElement` 变为空，按退出全屏处理：本次放映结束并回到预览，需要重新点击“进入放映”。
- 浏览器原生 `F11`/菜单全屏属于浏览器级全屏，不写入 `document.fullscreenElement`，因此**不视为进入放映**，也不会启动或推进本次放映；布局层不拦截 `F11`。
- Editor 的“放映”入口仍打开 Runtime 预览；受浏览器用户手势限制，最后一步“进入放映”必须在 Runtime 窗口内点击。

### 3.3 自动与手动

会话增加运行时开关 `autoAdvanceEnabled`，初始值来自 `auto_start`，只存在于本次放映，不写回 Backend。

| 当前页 `advance.mode` | 自动模式 | 手动模式 |
| :--- | :--- | :--- |
| `manual` | 等待用户上一页/下一页 | 等待用户上一页/下一页 |
| `timer` | 停留计时，到点自动下一页 | 不计时，等待用户翻页 |
| `media_end` | 播放媒体，结束后自动下一页 | 媒体继续播放，结束后不自动翻页 |

规则：

- 自动/手动只控制“页面是否自动前进”，不控制媒体播放。
- 自动切手动：取消当前页停留计时和媒体等待计时；页面不动，正在播放的媒体继续。
- 手动切自动：
  - `timer` 页从切换时刻重新开始一整轮停留时间；
  - `media_end` 页在媒体仍播放时等待结束，媒体已结束时按无媒体停留时间推进；
  - `manual` 页仍等待用户翻页，不因为会话切到自动就强行推进。
- 会话切到手动时，`manual` 配置页和自动配置页都停止自动推进；会话切到自动时，只有配置为自动的页面恢复自动推进。
- `transition` 在两种模式下都生效，手动翻页也播放整页转场。
- `loop` 只在自动模式生效；手动模式末页“下一页”不绕回首页。
- 后台标签页、冻结和 `pageshow` 恢复仍使用现有暂停逻辑；回到前台后显示“继续”，恢复后保持原自动/手动模式。

### 3.4 状态机

```text
非全屏（预览）
  │ 进入全屏
  ▼
preparing ──就绪──> playing
  │                  ├─ 自动：timer / media_end 推进
  │                  ├─ 手动：等待上一页/下一页
  │                  ├─ 系统中断 ──> paused ──继续──> playing
  │                  ├─ 自动末页且不循环 ──> ended
  │                  └─ 错误/受阻 ──> error / blocked
  │
  └─ 退出全屏 ──> 销毁控制器，回到预览
```

- 全屏内不存在“未开始”的独立状态：`auto_start=false` 直接进入手动会话。
- `paused` 只表示系统中断或媒体控制的临时暂停，不是主操作；主操作是自动/手动切换。
- `ended` 只由自动序列产生；手动模式在末页等待用户退出或切到自动。
- `error/blocked` 继续提供重试、下一页、退出。

### 3.5 翻页与就绪

- 手动上一页/下一页继续复用现有路由导航和 `notifyPageChange`：播放中翻页重置当前页计时，暂停中翻页保持暂停，旧 generation 的迟到结果被丢弃。
- 自动推进继续等待“路由提交 + 整页转场 `settled` + 必要视觉资源就绪”后开始停留或媒体等待。
- 媒体会话在自动和手动模式下都可以播放；手动模式不启用媒体超时，但实际播放错误/受阻仍然可见并可重试。
- 不新增第二套翻页状态机，也不在控制器外单独维护自动/手动计时。

## 4. Backend 配置参数

放映态直接使用项目路由产物中的 `playback` 和每页生效的 `meta.transition`/`meta.advance`，不额外请求 Backend。字段定义继续以 [contract.md](./contract.md) 为准。

| 参数 | 放映态行为 |
| :--- | :--- |
| `auto_start` | 进入全屏时的初始模式：自动或手动。字段不变，语义从“是否开始会话”改为“是否自动推进”。 |
| `transition.effect / duration_ms` | 自动和手动翻页共用的整页转场。 |
| `advance.mode` | 自动模式下当前页的推进方式；会话手动时强制等待。 |
| `advance.delay_ms` | `timer` 停留时间；`media_end` 无媒体时的回退时间。 |
| `media_timeout_ms` | 自动模式下的媒体等待上限；手动模式不启用。 |
| `loop` | 自动模式末页循环；手动模式不绕回。 |
| 逐页覆盖 | 继续由 Backend 解析为生效值，Runtime 按当前页读取；同一页面多次引用可不同。 |
| `hidden / page_number` | 决定放映序列；隐藏页不参与上一页/下一页和自动推进。 |
| `menu_mode / show_pdf_export` | 只属于预览壳；全屏放映不显示菜单、导出、卡片和缩略图。 |
| `speaker_notes` | 只进入演讲者控制台，不参与页面推进。 |
| 页面尺寸、主题、字体、样式 | 预览和放映共用，属于渲染配置。 |

- 不新增数据库迁移、DTO 或 External API 字段。
- Editor 配置文案建议改为“进入放映后自动推进”，并说明关闭时进入全屏后先手动翻页，可随时切换自动。
- CLI/MCP 文档同步说明 `auto_start` 的新运行语义；读写契约不变。

## 5. 界面与交互

### 5.1 预览态

- 保留现有侧栏、缩略图、卡片模式、导出和上一页/下一页。
- 不创建播放控制器，不显示放映控制条，不启动任何停留计时。
- 右上角“全屏”入口改为“进入放映”，点击后请求全屏并进入放映态。
- 预览工具栏保留“演讲”入口（`Shift+P` 同样可用）；从预览进入时没有本窗口放映会话，观众窗口按项目 `auto_start` 起步。
- 预览键盘：`→`/`↓`/`PageDown`/`空格` 下一页，`←`/`↑`/`PageUp` 上一页；`Home`/`End` 跳首末页；数字键跳页；`O` 打开卡片模式；`F` 进入放映；`Shift+P` 进入演讲。输入框和可编辑元素内不拦截。

### 5.2 放映态

控制条只保留：

```text
上一页 | 自动/手动 | 下一页 | 页码 | 自动剩余时间 / 手动 | 演讲 | 退出
```

- 自动模式显示剩余时间；手动模式显示“手动”。
- 控制条默认收起：指针进入窗口底部唤出区域时淡入，移开即淡出；暂停、错误、受阻、结束态以及无放映配置的旧产物保持显示。键盘 Tab 聚焦控制条时同样会唤出。
- 当前页配置为 `manual` 时显示“本页手动”，即使会话处于自动模式。
- 系统中断导致暂停时显示“继续”；不把暂停作为主操作。
- 媒体错误/受阻时显示重试和下一页。
- 结束态显示“重新开始”和“退出”。
- “退出”退出全屏并结束放映，不保留后台计时。

### 5.3 键盘

键位映射统一维护在 `runtime/src/runtime-shell/keyboard/keyboard-map.ts`（上下文 × 键位 × 动作），布局层只负责解析结果与执行动作。

| 场景 | 空格 / `→` / `↓` / `PageDown` | `←` / `↑` / `PageUp` | `Home` / `End` | 数字键 | 其他 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 预览 | 下一页 | 上一页 | 首/末页 | 跳页 | `O` 卡片模式；`F` 进入放映；`Shift+P` 演讲 |
| 放映 | 下一页 | 上一页 | 首/末页 | 跳页 | `Shift+P` 演讲 |
| 卡片模式 | 下一页 | 上一页 | 不处理 | 不处理 | `Esc` 关闭卡片 |
| 演讲者控制台 | 切换自动/手动 | 上一页/下一页 | 不处理 | 不处理 | 命令发送给观众窗口 |
| 观众窗口 | 不处理 | 不处理 | 不处理 | 不处理 | `Esc` 退出全屏并暂停 |

- 放映态不再由播放层独占空格：`usePlaybackHost` 不注册键盘监听，空格与方向键统一由布局层按下一页处理；布局层仍保留“焦点在按钮/链接上时空格不抢原生激活”的约束。
- 数字键跳页：总页数不超过 9 时立即跳转；超过 9 时缓冲最多两位，约 600ms 后提交，页码越界给出行内提示。`0` 只用于两位数缓冲。
- 不拦截 `F11`。`F11`/浏览器菜单全屏是浏览器级全屏，不触发 `fullscreenchange`，也不进入放映；进入放映由页面内“进入放映”按钮或 `F` 键调用 Fullscreen API。
- `fullscreenchange` 是进入/退出放映的唯一入口，且只认“根元素全屏”（进入）与“无全屏元素”（退出）两种状态。
- 预览与放映都可用 `Shift+P` 进入演讲。
- 输入框、文本域、下拉框和可编辑区不拦截；带 `Ctrl`/`Meta`/`Alt` 的组合一律不映射。

### 5.4 演讲者模式

```text
主窗口：演讲者控制台（窗口化）
  当前页 / 下一页缩略图
  演讲备注
  演讲用时（独立计时）
  自动/手动、上一页/下一页、退出
        │ 命令
        ▼
观众窗口：全屏放映本体（唯一推进者）
  只显示当前页和页面转场
  按 Backend 配置自动/手动推进
```

流程：

1. 在预览工具栏或放映控制条点击“演讲”，或在预览/全屏按 `Shift+P`。
2. 主窗口暂停并结束本窗口放映、退出全屏，切换为控制台。
3. 观众窗口打开并进入全屏，从当前页开始；从放映进入时继承运行时自动/手动模式，从预览进入时按项目 `auto_start` 起步。
4. 控制台的自动/手动、上一页/下一页、退出通过同步协议发送给观众窗口；观众窗口是唯一计时和推进者。
5. 观众窗口退出全屏、关闭或断开时，放映暂停，控制台显示状态；重新全屏并连接后才能继续。
6. 退出演讲关闭观众窗口，主窗口回到预览。

约束：

- 观众窗口必须全屏才能开始放映；未全屏时只显示进入全屏提示，控制台显示等待。
- 观众窗口是只读视图，不注册本地播放/翻页快捷键；控制台是唯一输入入口。
- 控制台合并原来的放映面板和页面按钮为一条传输栏；演讲计时仍独立，只表示演讲用时。
- 从放映进入演讲时把当前页和运行时自动/手动模式交给观众窗口；从预览进入时按项目 `auto_start` 起步，不伪造运行时状态。
- 同步协议增加 `autoAdvance` 状态和“设置自动推进”命令；双窗口同构建版本，必要时升级协议版本。
- 不创建第二个 `PlaybackController` 或第二个计时器。

## 6. 实施阶段

| 阶段 | 范围 | 退出条件 |
| :--- | :--- | :--- |
| P0：控制器自动/手动能力 | `PlaybackController` 增加 `autoAdvanceEnabled`、切换语义、计时/媒体守卫；`usePlaybackHost` 暴露切换 | 虚拟时钟覆盖自动/手动切换、计时重置、媒体继续、手动页不自动、循环边界 |
| P1：全屏放映壳 | 控制器只在全屏创建；预览去除控制条；放映工具栏、键盘、全屏失败提示、`auto_start` 初始模式 | 单元/组件测试覆盖预览无控制器、全屏进入/退出、键盘归属、系统中断 |
| P2：演讲者收敛 | 演讲入口迁移；观众窗口全屏门禁与只读；控制台传输栏；协议状态与命令 | 双窗口真实浏览器验证唯一调度、模式继承、观众只读、关闭重开、退出回预览 |
| P3：入口、文档与证据 | Editor 入口提示；用户/开发文档；WP31/WP33 入口与证据更新；旧按钮/旧文案清理 | 文档一致；构建产物/放映入口说明可复现；无残留重复控制 |

每个阶段单独可评审；P1 不依赖 P2，P2 以 P1 的放映壳为前置。

## 9. 风险与已知限制

- **Editor 手势限制**：Editor 新窗口无法可靠自动请求全屏，用户必须在 Runtime 窗口点击“进入放映”。Editor 入口文案需要说明这一点。
- **M3/无人值守入口**：直接打开构建链接默认是预览，`auto_start` 不再在窗口内自动推进；无人值守需要全屏点击或 kiosk/自动化，WP31/WP33 的入口与证据必须更新。产品级无人值守仍不在本规划范围。
- **全屏失败**：按本规划不提供窗口放映 fallback；不支持全屏的环境无法进入放映。若后续需要，另设明确的窗口放映例外。
- **内容元素全屏**：视频、Mermaid、Drawio 等元素全屏期间放映继续，但不暂停页面推进；Chromium 退出元素全屏后不会恢复根全屏，因此本次放映结束并回到预览。“退出元素全屏后继续放映”需要重新请求根元素全屏，作为后续增强项。
- **F11 与浏览器级全屏**：`F11`/浏览器菜单全屏不写 `document.fullscreenElement`，不进入放映，页面仍是带侧栏和缩略图的预览；浏览器级快捷键不能被页面可靠拦截。进入放映由页面内“进入放映”按钮或 `F` 键触发（两者都要求 Runtime 窗口内的用户手势）。
- **演讲遥控器**：观众窗口只读，演示遥控器需要把按键发送到控制台窗口；如果必须让观众窗口响应，另行设计转发，不恢复第二个调度器。
- **协议版本**：增加状态/命令可能要求升级演讲同步协议版本；双窗口同构建版本，需同步更新协议测试和双窗口证据。
- **既有预期变化**：全屏预览带侧栏/缩略图的行为被移除；空白键在放映态含义改变；用户文档和旧截图需要更新。
- **旧产物兼容**：不带 `playback` 配置的旧 artifact 仍可进入全屏，但控制条只显示“当前项目未启用放映配置”和退出，不渲染上一页/下一页与自动/手动按钮，翻页依赖方向键/PageUp/PageDown；预览态控件在全屏时已隐藏。需要重新构建产物才能获得完整控制条和自动/手动切换。
- **浏览器范围**：继续以桌面 Chromium 为验收目标；Firefox/WebKit 和移动端不作为本次支持承诺。

## 10. 已采纳决策与待确认项

已采纳：

- 非全屏 = 预览，全屏 = 放映；退出全屏结束放映。
- 进入全屏即启动会话；`auto_start` 决定初始自动/手动，不再决定“是否开始”。
- 自动/手动是本次放映的运行时状态，不写回 Backend。
- 手动不是暂停：媒体继续，只停止页面自动推进。
- 自动切手动取消计时；手动切自动时 `timer` 重新计一整轮，`media_end` 按媒体状态或回退停留处理。
- `manual` 配置页在自动会话中仍手动；`loop` 只作用于自动推进。
- 控制条以自动/手动为主操作，保留系统暂停后的“继续”。
- 演讲者模式以观众窗口为唯一放映本体，控制台只发命令；观众窗口全屏且只读。
- 预览工具栏保留“演讲”入口：从预览进入时观众窗口按 `auto_start` 起步；从放映控制条进入时继承当前自动/手动模式。
- 不新增 `runtimeMode`、播放布局、Backend 字段或迁移。

实施时待确认（已决）：

- 无人值守/本地构建入口：直接打开构建链接仍是预览；需要用户点击全屏按钮，kiosk/自动化入口另行设计，WP31/WP33 已补充说明。
- 演讲同步协议：升级到 v3，双窗口必须同构建版本；旧协议消息被拒绝。
- 内容元素全屏：视频等页面内元素全屏期间放映继续，也不同步暂停推进；退出该元素全屏后 `fullscreenElement` 为空，按退出全屏结束放映并回到预览（Chromium 不恢复根全屏）。
- 浏览器全屏：`F11`/菜单全屏不进入放映，也不被页面拦截；放映入口只有“进入放映”按钮。
- Editor 引导：入口提示说明“在 Runtime 窗口点击进入放映”，不自动请求全屏。

## 12. 复核勘误与设计约定（2026-10-18）

评审复核发现两处文档与实现不一致，已按实际实现更正；两项交互确认为设计意图，补充说明以便后续维护：

- **F11 不是放映入口**：原 §3.2/§5.3 写“F11/菜单全屏同样视为进入放映”，实际浏览器级全屏不写 `document.fullscreenElement`，`isFullscreen` 保持 false，只得到带预览控件的窗口全屏。已更正为“不拦截、也不进入放映”。
- **退出元素全屏会结束放映**：原用户文档写“退出元素全屏后返回放映”，实际 Chromium 退出元素全屏后 `fullscreenElement` 为空，`handleFullscreenChange` 按退出全屏处理。已更正为“元素全屏期间继续放映，退出后结束并回预览”。
- **重开的观众窗口不继承临时模式**：`openDisplayWindow()` 只带当前页，不带 `autoAdvance`，因此重开的观众窗口按项目 `auto_start` 初始化；控制台随后按观众回执刷新自动/手动显示。这是设计意图：观众窗口始终以构建产物配置为基准，避免跨窗口残留状态。
- **控制台键盘不受观众全屏门禁限制**：传输栏按钮在观众窗口未全屏时禁用，但控制台方向键/空格仍向已连接的观众发送命令。这是设计意图：演讲者无需先聚焦按钮即可操作；观众侧对 `start/resume` 要求全屏，其余命令在放映未启动时被吸收。
