# 首期编排验收计划

状态：**G0 功能选型通过，G1/G2 未执行。** 2026-10-21 采用 GSAP 与受控原生视觉＋资源 builder，详见[G0 决定](./g0-decision.md)。本轮不比较性能；第一轮数字保留为历史候选。

## G0 技术与创作验证

WP01 已完成四候选基础核对、真实资源六组合、前一轮 Luna 小样及最终固定适配模板。最终采用八个新 Luna 上下文，生成/修改/复用/修复各两例；出口预设至少7/8首次通过、8/8在一次反馈内通过，实际8/8首次通过。裁剪后的最小执行依赖包、独立静态构建八例及媒体交接/卸载通过。该结果选择引擎与默认形状，不代替正式 G2 多任务基准或完整产品镜像。

下表仅保留第一轮的性能/规模候选，当前未冻结、不作为本轮比较依据。创作方式确定后，再固定参考设备与媒体条件复核这些目标，不能在最终失败后临时放宽：

| 项目 | 第一轮候选与测量方式（待后续复核） |
| :--- | :--- |
| 暂停响应 | 前台从命令接受到可观察位置停止 p95 ≤100ms |
| 同步漂移 | 稳态前台 30fps 受控样例 p95 ≤80ms、最大 ≤160ms；buffering/seek 单独统计，不混入稳态 |
| 温缓存定位 | 从 seek 命令接受到目标状态 ready p95 ≤1000ms；网络冷启动单独记录 |
| 确定采样 | 同设备同输入，直接采样 t 与乱序采样后回到 t 的规范状态一致、截图逐像素一致；固化前后单通道差 >8 的像素不超过 0.1%（实测 0） |
| 规模 | 每页最多 64 总轨道、32 总目标、有限主时长 30 分钟；长时间播放仍需 G2 soak |
| 清理 | 100 次进出/重播后无遗留播放者、计时或 RAF；稳定采样窗口无持续资源增长 |

G0 输出执行器/创作形状、样本来源、真实功能证据与最小裁剪交付方法。用户明确要求性能后置，性能/规模阈值不作为本轮关闭条件；仍需在后续实现与 WP12 中单独验证，不能因 G0 通过而默认为达标。

| A10 | 旧媒体与新所有权 | 独立内容媒体仍手动；同步媒体不被两个会话 play/pause/归零或重复计入完成 |

| A12 | 偏好与静态状态 | system/reduced/full 来源正确，视觉降动效不误静音、不误触发完成，捕获不能被放宽 |
| A13 | 指定状态捕获 | poster、标签、时间点贯穿远程请求和回执；解码帧/骨骼/DOM 已固化，兜底禁动画不改帧 |

纯算法使用虚拟时钟与共享用例；媒体、WebGL、iframe 与真实截图必须用真实浏览器。单测中的 play Promise mock 不能替代 A06–A10、A13–A16。

## G2 发布与模型创作基准

G2 要求 G1 全部关闭，并完成以下联合场景：

- Editor 页面预览显式播放、暂停、重播、定位、偏好模拟和默认 poster；响应式控件遵守根 DESIGN。
- 同一示例通过内置助手、CLI 与 MCP 读取能力、创建、修改、等待 mutation job、查询最终版本并获取默认/临时截图。
- 真实 Backend 桥接页与独立 Runtime 源站，受保护视频/audio 的 HEAD、Range 与跳转定位；不依赖 public fallback。
- 生产依赖裁剪后的镜像可启动，独立构建脱离开发服务器播放并可静态导出；新 Runtime Kit 的依赖闭包与资源完整。
- 新旧放映配置、v1/v2 渲染协议、旧 v1 Asset 组件与新 v2 内容的混版行为符合运行契约；不支持时明确失败。
- 至少 30 分钟受控循环，记录漂移、卡顿、JS 堆、媒体元素、RAF/计时器、WebGL 资源和浏览器进程；不把本地验收扩展成无人值守全天承诺。

### 八个模型任务

G0 原型及独立 Luna 小样用于检查创作表达性和反馈恢复，任务/样本方法单独保存，不与本表正式 G2 基准混计。G2 固定模型与版本、工具集合、系统规范、种子资源和每任务修正轮数，记录 token/耗时，不借机发送用户业务消息或修改开发数据。

| 编号 | 任务 |
| :--- | :--- |
| B01 | 标题与三张图片错峰进入，静态海报可读 |
| B02 | 旁白作为主媒体，同步两段说明文字 |
| B03 | 从真实查询动作中选择模型片段，和标题同时开始 |
| B04 | 模型动作结束 200ms 后播放裁切且静音的视频 |
| B05 | 将 B04 的模型动作延后 500ms，后继自动顺延 |
| B06 | 同一模型两个实例分别停在不同时间并截图 |
| B07 | 根据轨道属性冲突与过期动作引用错误修复 |
| B08 | 区分 reduce、blocked、buffering 与静态截图，给出与证据一致的解释 |

候选发布目标：至少 7/8 首轮编译与业务校验通过，8/8 在最多一轮有界错误反馈后通过；B05 不修改无关轨道，B08 不编造已检测状态。记录失败样例与 API 修改原因；若达不到，先简化接口或错误反馈，不以增加长提示掩盖接口问题。

### 支持矩阵与证据

桌面 Chromium 是首期发布基线。Firefox/WebKit、移动端、直播、第三方 iframe、跨页 BGM 和离线视频导出未验证时明确不列入支持范围。媒体容差基于实际解码帧率，不承诺任意设备严格帧同步。

证据至少包含代码版本、Schema/引擎版本、设备/浏览器、命令、样例 hash、轨道计划摘要、时序记录、可读产物和未运行项。Renderer 还记录同 attempt 的状态回执、PNG、取消清理和槽位释放。文档中的测试通过只描述实际跑过的命令。
