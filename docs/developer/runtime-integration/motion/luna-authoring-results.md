# Luna 独立编写 Vue SFC 的验证结果

日期：2026-10-21。这是前一轮四上下文过程记录，通过 collaboration 显式指定 `gpt-6-luna`、medium、`fork_turns: none`。当时结论是 GSAP 稍稳、需要固定生命周期模板；本阶段未关闭 G0。后续固定模板的八任务和交付验证已完成，最终结论见[G0 决定](./g0-decision.md)。不比较性能、不开放新 Runtime Kit 能力。

## 试验方法

每款引擎各做 native 资源计划和 builder 资源计划，共四个独立首次实现。固定的故事、真实媒体、GLB、模板、SDK 与行为要求相同，差别仅为引擎和资源计划写法。模型自行写视觉时间轴、资源调用与生命周期连接，父模型只实现测试夹具和执行评分，没有代写或修补候选。

首轮模型禁止运行测试，交付后先保存源码再测；每阶段最多一轮有界错误反馈，由同一 Luna 修复。首次任务 A 修复后仍失败则停止，不参加 B/C/D。通过者继续做默认段落延后、函数复用，以及统一注入故障后的修复。精确任务与[协议](../../../../tests/experiments/motion-luna/protocol.json)见夹具；派发提示和逐阶段记录只保留在本地研究归档，不随仓库提交。

允许读取固定 SDK/类型/模板及自己候选的官方文档和发布类型，禁止读取既有答案、另一候选、研究结论和测试断言。各组上下文独立，但文件系统共享，读取边界通过指令约束，没有操作系统级隔离。只获得所请求的模型名与 effort，没有内部模型版本、seed 或 token 数据。这是四上下文创作小样，不能外推所有弱模型或统计显著性。

评分前为共同 SDK 补齐任务所需的 Draft 类型重导出，未修改候选，未计作模型修复。之后评分输入保持不变，所有阶段的输入 hash 可核对。

## 首次实现与一次反馈

| 候选 | 首轮严格类型 | 首轮完整要求 | 一轮反馈后 | 主要问题 |
| :--- | :--- | :--- | :--- | :--- |
| GSAP native | 通过 | 未通过 | 通过 | 未静默定位；越过资源桥接重复采样/释放模型 |
| GSAP builder | 通过 | 未通过 | 通过 | fromTo 关闭 immediateRender 后，开始前初态未建立 |
| Anime.js native | 未通过 | 未通过 | 仍未通过 | Scope 回调返回值/不存在的 animations 属性；修正类型后仍有初态和静默问题 |
| Anime.js builder | 通过 | 未通过 | 通过 | 未来动画初态未建立；seek 未抑制回调 |

四个首轮中三个可严格编译，但没有一个满足全部行为要求。一次反馈后三个通过，Anime.js native 按预定预算停止，没有追加第二轮修复，也没有由父模型修好后再计成功。

GSAP native 不是不会表达效果，而是违反资源控制边界且定位没有抑制回调；删去重复模型操作、启用静默定位后通过。GSAP builder 显式建立初态后通过。Anime.js native 把 Scope 当成可读取 animations 的容器，构造回调还返回了错误类型，修复类型时没有同时解决下一层运行要求。Anime.js builder 在一次反馈后建立初态、抑制 seek 回调，通过同一检查。

失败诊断来自严格 Vue/TS、真实 DOM opacity/位移、视频解码内容、骨骼状态、乱序恢复、双实例作用域、PNG 固化、过期 clip 和资源控制权检查。测试为了验证静默定位，通过公开时间控制方法向候选实际使用的时间轴加入一个 100ms 计数回调；它不控制媒体、不改源码，预期任意 sample 都不补发该回调。不能仅凭候选注释写了“静默”判通过。

## 增量修改与故障恢复

| 候选 | B：段落延后 | C：函数复用两组错峰 | D：统一故障一轮修复 |
| :--- | :--- | :--- | :--- |
| GSAP native | 首次通过 | 首次通过 | 通过 |
| GSAP builder | 首次通过 | 首次通过 | 通过 |
| Anime.js native | 未参加 | 未参加 | 未参加 |
| Anime.js builder | 首次通过 | 首次通过 | 通过 |

B 只把默认动作起点从 1200ms 改到 1700ms，旁白/标题/三卡保持原时间，视频与字幕顺延。三个候选的源码均只改变这一处默认值，hash 对照证明没有附带修改。

C 在模型和视频各自开始后 100ms，用同一个函数编排各三个 chip：每项 200ms、错峰 80ms、线性 opacity 0→1 与 y 12→0。三组首次修改均通过，同时保留全部既有行为。没有看到 Anime.js builder 在掌握初始规则后持续落后的证据。

D 由评测器统一把一次 `.clip-caption` 改成 `.clip-captino`，先保存并确认实际失败，再提供相同行为反馈，由原 Luna 修复。三组均一次修正，最终源码 hash 与 C 的原版本完全相同。这些注入失败不计作模型生成失败；它们验证的是利用有界反馈恢复局部错误。

全部 20 个阶段的源码、状态、版本、失败字段、注入规则与 hash 记录在本地研究归档（不随仓库提交）。其中包含应保留的失败，不应把“20 阶段已执行”说成“20 次全部通过”。

## 对选型的影响

**继续优先 GSAP。** 本次两个 GSAP 上下文都可首轮严格编译并在一次反馈后完成基础任务；Anime.js 两个上下文中一个达到相同结果，一个在类型与行为之间出现连续错误。加上[上轮原生嵌套静默定位](./story-authoring-comparison.md)的差异，GSAP 当前有更具体的工程支持，但样本不足以宣称普遍生成成功率更高。

**Anime.js 不淘汰。** builder 组修复后，段落延后、函数复用和错误恢复均与 GSAP 一样首次通过。不能把一次 Scope API 误用扩展成库整体不适合模型编写。

**没有证据说明资源 builder 已提升首次通过率。** 两个 builder 首轮也失败，问题主要落在视觉初始化和静默控制；native 的资源计划算式本身没有出现时长计算错误。builder 的可校验依赖与减少手工映射仍有设计价值，但这轮不能拿两个样例证明其成功率优势。

本次没有新增 Motion 或 WAAPI 的独立模型创作对照，因此不据此再给它们排名。主线仍是 GSAP 优先、Anime.js 主要备选，Motion 保留声明式参照，裸 WAAPI 退出完整编排主方案。

## Runtime 应减少的创作负担

本次最一致的信号是：**不要让每个页面反复实现正确的初始化、静默 sample 和生命周期。** 下一版原型应提供固定、类型明确的引擎适配模板，模型主要写视觉段落和资源依赖：

- Runtime 创建并登记作用域和暂停时间轴，明确应用未来轨道初态；统一进行静默定位、固化、最终撤销。候选不再自行通过 Scope 寻找时间轴，也不反复猜初始化参数。
- 统一以毫秒进入适配器，在 GSAP 边界集中换算秒；资源 builder 只维护实际资源与命名依赖，不复制全部视觉属性 API。
- 对创作代码提供窄 authoring context：目标绑定、资源摘要和受控句柄；内部 Mixer、模型 sample/dispose、原始媒体控制对象不要全部塞进 factory 输入，再只靠提示要求模型不碰。
- 保留短而具体的模型指南和有界诊断：动画开始前初态、静默定位、唯一播放所有者、卸载、实际 clip 引用。不能只告诉模型“用 GSAP/Anime.js 写动画”后期待其自行补齐平台约束。

上述是下一版 SDK 的设计建议，未在本轮发布适配器。还需用固定适配模板对同一模型重测，并增加独立重复样例和更多任务，才能区分库 API、模板和模型随机性各自的影响。

## 验证范围

使用 GSAP 3.15.0、Anime.js 4.5.0、Vue 3.5.34；新编排 SFC/TS 严格检查，旧媒体/模型 MJS helper 沿用上一轮。真实播放时钟已经由完整故事夹具验证，本轮 Luna 使用共享 SDK，未重新实现或独立验证 transport。没有启动产品服务或修改业务数据、生产依赖、系统减少动态效果设置与 Runtime Kit manifest。

本阶段执行四组首次实现/反馈、三组 B/C/D，全20阶段保存；核对20份源码、160个评分输入 hash、三处精确默认值修改和三处完整还原。`test:repository` 8文件63项、MJS语法及差异检查通过。本阶段未跑独立构建；后续固定模板的八任务和最小裁剪交付已通过、关闭功能 G0。完整生产门禁、业务 E2E、跨浏览器、性能与正式 G2 基准仍未验收。
