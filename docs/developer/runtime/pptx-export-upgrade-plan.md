# Runtime PPTX 导出升级规划

规划日期：2026-10-13；最近复核：2026-10-14。状态：S0 至 S5 的首批实现及复核修复已落地，各阶段仍按下文退出条件验收。评估基线：`caf5d4bc85553aa476829235460a659b3dca0bc2`；本次复核覆盖 `393573a` 至 `78e1e81` 的六个实施提交。本地 PptxGenJS 版本为 `4.0.1`。

本次升级保留 DOM 采集、单页中间表示和文档写入的现有分层，先解决取消后仍下载、离屏投影失真和内容丢失，再完善视觉映射、性能和原生编辑能力。原生图表、对象组合和母版分别验收，不作为基础修复的发布前提。性能收益以固定样本的实测结果为准。

## 1 目标与修改范围

升级后的导出应满足以下目标：

- 取消任务后不触发文件下载，旧任务不能更新或清理新任务的状态。
- 导出使用固定画布中的实际页面状态，动画最终态、响应式样式和资源上下文保持一致。
- 可见文本、换行、表格内容和页面顺序保持完整；无法原生表达的视觉效果有明确降级结果。
- 每个源对象、生成图元、降级原因和阶段耗时可关联，报告能区分正常图片与能力降级。
- 常见文本、形状和表格保持可编辑；原生列表、组合和图表按明确支持范围逐步增加。

主要修改范围为 `runtime/src/core/services/PPTXExportService.ts`、`services/export/`、`services/pptx/`、`runtime-shell/export/` 及相关测试。涉及图表数据契约时联动 Runtime Kit viewer，涉及公开能力变更时才联动 manifest 和 Backend 契约。

PPTX 浏览器导出不新增 Backend 浏览器执行，不改变 Renderer 截图队列或部署角色。共享捕获和任务模块的改动必须回归 PDF、浏览器打印与已有截图调用方。新增导出内部能力不进入 `@runtime-kit` 公开能力目录。

## 2 两份评估的核实结果

### 可以采纳的结论

| 事项 | 已核实的现状 | 规划决定 |
| --- | --- | --- |
| 现有架构 | 已有 `PptxSlideIR`、报告构建器、图元投射器和包写入器 | 保留分层，收紧输入、输出和每任务状态 |
| 离屏投影 | `outerHTML` 克隆和宿主样式注入会重新执行动画、按宿主视口解释媒体查询 | 优先改为在 iframe 文档中测量、提取和截图 |
| 渐变 | 只识别四个正交方向；根背景、圆角及重复背景存在额外缺陷 | 先统一视觉分派，再增加任意角度 |
| 阴影和行距 | 没有原生 `box-shadow` 映射，正文未写入行距选项 | 支持有界的单层外阴影和明确行高，完成应用侧对拍 |
| 缩放 | 非单位缩放进入不支持分支并截图 | 先支持正值等比缩放；非等比、镜像和倾斜继续降级 |
| 编辑语义 | 图表输出 SVG 或 PNG；没有原生列表和真正的对象组合 | 分别建立段落、组合、图表语义，避免从截图反推数据 |
| 多页容错 | 未捕获的单页异常会终止整个导出；局部截图已有跳过报告 | 增加受约束的页面容错，保留失败和取消的区别 |
| 诊断 | 当前报告主要是类型计数与文本明细 | 增加严重级别、稳定原因码、对象关联和脱敏 JSON |

PptxGenJS `4.0.1` 的本地类型和实现已提供 `lineSpacing`、`lineSpacingMultiple`、`shadow`、段落 `bullet`、`addChart` 和 `defineSlideMaster`。这只确认底层入口存在，不代表 HTML 样式可以直接无损映射，也不代表 Runtime 已支持这些能力。

### 需要纠正或限定的结论

1. **每页赋值 `frame.src` 不等于每页冷启动。** [离屏舞台](../../../runtime/src/core/services/export/OffscreenPageStage.ts)只修改当前地址的 hash，[项目路由](../../../runtime/src/core/router/project-router.ts)使用 `createWebHashHistory()`。调用真实舞台实现的受控 Chromium 实验中，三次切页的 iframe 启动标识和 `performance.timeOrigin` 相同，文档请求共两次，分别为宿主和首次 iframe 加载。因此不把“每页全量下载 JS/CSS”作为当前瓶颈，也不新增通用 `__ROUTER__` 全局入口作为首个优化。
2. **2～5 倍提速、全屏重排和内存泄漏尚无基准支持。** 宿主样式注入、克隆和重复资源读取有优化价值，但具体成本、释放结果和收益须分别测量。
3. **不支持的渐变不一定退成纯色。** 无文字的小渐变块会截图；含文字或大面积容器的处理取决于分派和面积规则。已用 `45deg` 无文字样例确认截图路径。实际问题是不同分支会产生截图、效果丢失或无提示近似，需要统一策略。
4. **复杂容器的背景、边框和圆角并非一律消失。** [转换器](../../../runtime/src/core/services/pptx/PPTXDomConverter.ts)记录 `skipped` 后仍继续文本和形状转换。滤镜样例仍输出带底色、边框、圆角的文本形状；丢失的是滤镜等合成效果。不能通过机械补一张背景截图解决所有 `filter`、`backdrop-filter` 和混合模式。
5. **渐变角度不能直接用 CSS 角度乘以 60000。** CSS 的零度指向上方；DrawingML 的方向向量采用另一套基准。对已解析的 CSS 数值角度、且写入 `scaled="0"` 的路径，方向候选为 `((cssAngle - 90) % 360 + 360) % 360`，之后才转换为 OOXML 单位。角落关键字还依赖背景盒宽高，必须连同停靠点和渐变范围验证。依据 [CSS Images 线性渐变定义](https://www.w3.org/TR/css-images-3/#linear-gradients)和 [DrawingML LinearGradientFill](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.lineargradientfill?view=openxml-3.0.1)。
6. **缩放不能直接再次乘到实测宽高。** `getBoundingClientRect()` 已包含变换效果。新实现应从明确的局部坐标和仿射变换计算最终几何，字号、padding、边框和阴影只应用一次缩放。
7. **组合不是简单包裹 XML 标签。** 需要稳定图元 ID、正确的组坐标、子坐标和绘制顺序；不连续图层不能随意归组。DrawingML 组变换显式包含 `off/ext/chOff/chExt`，见 [TransformGroup](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.drawing.transformgroup?view=openxml-3.0.1)。

## 3 目标架构与模块边界

```mermaid
flowchart LR
  A[任务上下文和配置快照] --> B[iframe 页面句柄和就绪协议]
  B --> C[页面文档内测量与提取]
  C --> D[验证单页 IR 和选择降级]
  D --> E[投射到 PPTX 文档]
  E --> F[打包和 OOXML 后处理]
  F --> G[任务复核后下载]
  C --> H[对象诊断和阶段指标]
  D --> H
  F --> H
```

### 每任务上下文

任务上下文持有 ID、取消信号、总期限、阶段状态和不可变导出快照。快照包含页面顺序、完整路由及查询参数、画布尺寸、主题和字体上下文、资源上下文、备注与文件名。配置变化不应改变正在生成的幻灯片比例或内容。

`cancel()` 发出取消信号并进入释放过程，互斥占用保持到清理完成；界面在可重试前展示释放状态。更新状态、上报进度、提交文件与清理都核对任务 ID。转换器不复用跨任务的可变 `options/reportPage/layout`，富文本等缓存按页面生命周期重建。

写入器拆分“生成字节”和“下载文件”。异步生成结束后再复核任务，取消、过期或旧任务结果均不能触发下载；不能中断的底层操作可以自然结束，但不得提交结果。共享 `ExportTaskRunner` 的变更必须保持其他导出服务的生命周期语义。

### 页面文档内采集

舞台提供页面句柄，包含目标元素、所属 `Document/Window`、请求标识、就绪状态和释放能力。布局、颜色、富文本、SVG、Canvas、图片与截图统一通过页面环境读取，避免主窗口 `instanceof HTMLElement`、全局 `document.createRange()` 或 `window.getComputedStyle()` 判错跨窗口节点。

就绪校验绑定本次请求、完整路由和当前目标页面，不能只凭上一页留下的布尔就绪标记。复用 [render-ready.v1](../../../runtime/src/core/utils/render-ready.ts)的字体、资源和错误语义，必要时增量加入切页请求回执；保留有限动画等待和无限动画静态化规则。字体、图片、SVG 源读取和截图均受任务总期限约束。

优先移除 PPTX 的宿主 `outerHTML` 投影与全局样式注入。局部截图也要在目标文档的环境中执行；不能把读取 iframe DOM 的改造停在布局层，再把截图送回依赖主文档的旧路径。PDF 使用的共享舞台以兼容适配方式迁移，回归资源代理、外部 SVG defs、Canvas、视频封面、透明背景和清理。

### 中间表示和视觉决策

IR 保持纯数据和可序列化。按图元定义几何、文本段落、填充、边框、图像和资源引用，不把 DOM、ECharts 实例或 PptxGenJS 内部对象存进去。生产路径逐步收紧 `Record<string, unknown>`，底层类型和字段转换集中在 writer 适配层。

增加唯一 `sourceId`、`primitiveId` 与诊断关联；多个能力记录可以指向同一个真实图元。PPT 对象名继续用于选择窗格展示，不能因截断或同名而承担唯一身份。新视觉决策先解析元素整体效果，再选择原生、近似或截图路径，避免媒体、背景、渐变和文本各自重复绘制。

一页先提取并验证 IR，再创建并投射 slide。允许页面降级时，失败 IR 整页丢弃后再生成截图 IR，不能在已写入部分内容的 slide 上叠加全页图片。投射或打包阶段无法原子恢复的错误按文档失败处理。

## 4 分阶段工作包

阶段编号表示实施顺序，P0/P1/P2 表示优先级。阶段完成以退出条件和产物证据为准，不以代码合并或用例数量作为唯一依据。

| 阶段 | 优先级 | 主要结果 | 前置条件 |
| --- | --- | --- | --- |

| S1 页面环境迁移 | P0 | 在真实 iframe 文档提取和截图，移除 PPTX 宿主投影 | S0 任务隔离与测试样本 |
| S2 视觉和排版映射 | P1 | 绘制顺序、裁切、背景、行距、阴影和受约束缩放 | S1 页面环境稳定 |
| S3 性能和诊断 | P1 | 页面容错、资源复用、打包 Worker、可核验报告 | S0 至 S2 的 IR 与降级语义 |

### S0 任务和内容修复

建议拆为生命周期、文本、背景三个提交单元，每项附可复现样例。

- 将取消信号和任务 ID 校验贯穿准备、转换、资源读取、打包和下载。给图片、SVG 源与字体等待增加有界期限；取消不记为页面失败或截图降级。
- 隔离转换器状态和页面缓存；导出快照固定尺寸、路由、备注和资源上下文。
- 修复隐藏 inline、`br`、连续空行和空白语义；让表格复用字符级解析，并扩展当前只允许字符串的单元格类型，保留局部字体样式。
- 将根背景纳入视觉提取；渐变复用圆角几何，阻止重复纯色填充覆盖背景。保留正圆、圆角方框、胶囊和 padding 的现有约束。
- 给报告加入源对象与真实图元身份，先区分交付成功、能力降级与内容遗漏。
- 将本次临时探针迁入长期测试，并建立性能样本与阶段计时，供 S3 比较。

退出条件：取消期间零下载；取消后重试状态不串扰；表格“甲换行乙”及局部加粗保留；隐藏文字不进入 XML；根渐变、圆角渐变和有子内容的渐变容器正确输出，无重复遮盖。

### S1 页面环境迁移

- 建立内部页面环境适配层，使所有 DOM 读取与类型判断使用目标文档；不通过随意注入全局 Vue Router 实例解决跨窗口问题。
- 在复用 iframe 的 hash 导航上增加本次请求与就绪状态关联，覆盖 query 变化、相同路径重复导出、资源失败和超时。
- 完成 PPTX 原生采集与局部截图的页面环境迁移，取消时终止舞台导航或等待并释放资源。
- 保留必要的兼容适配层，联动回归 PDF 和普通页面捕获；确认主窗口路由、样式、主题和滚动状态没有副作用。

退出条件：同一页面在不同宿主视口下生成相同几何；动画最终态不重新开始；三页切换无上一页残留；字体、Canvas、SVG defs、封面图和资源代理均可用；成功、失败、取消后无遗留舞台或投影节点。

### S2 视觉和排版映射

本阶段先完成基础背景与文本，再推进需要子树合成的层级和裁切。

- 建立受约束的层叠上下文模型，考虑定位、负层级、Flex/Grid 重排和合成效果。不能只对全部节点全局排序 `z-index`。不支持的层叠关系降级到最小可独立截图的子树。
- 保留负坐标和原始几何，由页面边界或明确裁切区域决定可见范围。矩形裁切优先原生映射；圆角裁切、遮罩和复杂路径在能力不足时截图，不能通过归零位置模拟裁切。
- 明确祖先透明度与组混合效果。简单不重叠图元可计算有效透明度；重叠子树不能用逐个乘 alpha 等价替代组透明度，应整体合成或使用已验证的组能力。
- 统一纯色、图片、渐变、边框与圆角的绘制职责；处理媒体自身和祖先的效果。移除大面积复杂容器的无报告豁免，按视觉能力和合成范围决定降级，不再仅凭面积跳过效果。
- 增加 `deg/rad/turn` 和角落关键字渐变，按最终背景盒解析方向和停靠点；验证非正方形、透明停靠点、边界停靠点和旋转。无法表达的多层背景保持明确截图降级。
- 映射明确的 `line-height` 与段落间距。固定行高优先验证 `lineSpacing` 的物理点值，倍数行高验证 `lineSpacingMultiple`；混合字号和字体映射场景单独校准，不直接假设 `lineHeight/fontSize` 无损。
- 支持单层、无 spread 的外阴影，偏移和模糊通过现有 px 到 pt 坐标换算；多层、内阴影、spread 或依赖背景采样的效果继续有界降级。
- 首批支持正值等比缩放及其与旋转的组合，统一换算文字、padding、线宽和阴影。非等比文字缩放、镜像、倾斜和 3D 保持截图路径。
- 对 `filter/backdrop-filter/mix-blend-mode` 按真实合成范围处理。能独立分离背景时保留背景和可编辑文字；涉及文字滤镜或背景采样时优先保证视觉，并明确说明截图范围。

退出条件：固定样本的遮挡顺序、裁切、透明度、渐变、行距、阴影和缩放符合预期；未支持样例均有明确报告；既有原生表格、旋转、正圆、公式多段 SVG 和连接线紧边界回归通过。

### S3 性能和诊断

- 资源解析统一缓存 Promise 和解析后的内容类型、尺寸、字节数据；缓存仅在任务内复用，键包含资源身份和必要上下文，取消或完成后释放。资源预取采用有界并发，页面 DOM 采集保持串行。
- 只对静态测量阶段缓存样式与盒模型，变换准备、DOM 修改或截图操作使相关缓存失效，避免缓存旧位置。
- PNG 截图用 `rasterScale` 或明确像素预算表达清晰度；将现有未生效的 `quality` 契约迁移或明确弃用，不能继续暗示 PNG 质量参数已生效。
- 把 OOXML 后处理移入 Worker 或其他已验证的异步打包路径，减少压缩后的整包重复压缩和无必要复制；渐变按稳定图元 ID 定位，验证命中数量和 XML，不允许缺失目标静默通过。
- 提供阶段进度、耗时、资源字节、截图次数、产物大小与取消延迟。正常图片归为正常结果，图表栅格化、效果近似、截图失败和内容遗漏分别归类。
- 报告支持按页、严重级别与原因筛选，复制或下载诊断 JSON；资源 URL 去除令牌等凭证。真实图元计数与能力计数分开，原生图片不计入“失败”；暂不把简单对象占比命名为视觉质量分数。
- 增加 `fail-fast` 与 `rasterize-ready-page` 页面错误策略。首次上线默认保持 `fail-fast`；完成截图容错验收后由界面提供明确选择，结果标注哪些页面变为整页图片。

整页容错只处理已就绪且仍可捕获页面的可恢复提取错误。取消、权限或资源上下文失效、目标页面未就绪、全页截图失败、不可恢复投射与打包错误不吞掉。失败页不静默删除，不保存空白占位页；成功交付截图文稿时必须显示降级状态和原因。

退出条件：可恢复页面失败后产物页数、顺序和备注正确，失败页仅有一份完整内容；取消不触发容错或下载；重复资源明显减少读取次数；性能预算与改造前后的阶段指标有可复核记录；诊断 JSON 可关联真实产物。

### S4 原生编辑语义

按原生列表、对象组合、图表三个独立工作包交付。

- **列表**：增加段落 IR，支持简单 `ul/ol/li`、起始编号和分级缩进，保留段落内 rich text。自定义 marker、图片 marker、复杂布局或无法表达的编号形式采用明确降级；验证在目标应用回车后仍保持列表语义。
- **组合**：增加显式组节点与成员图元 ID，按语义容器选择组合，不把所有 HTML 布局容器自动归组。保持绘制顺序与绝对位置，正确写入组和子坐标，覆盖嵌套组、负坐标、旋转、超链接、图片关系和拆组编辑。跨层交错对象不强行组合。
- **图表**：先冻结版本化导出数据 Schema，再支持简单柱状图、折线图、饼图和环形图。通过 Runtime Kit 明确输出经过归一化的系列和标签数据，不读取私有 ECharts 实例，不从 SVG 反向恢复数据。载荷有大小和类型边界；复杂 dataset transform、函数 formatter、多坐标轴、组合图、渐变系列和扩展图形继续 SVG/PNG 路径。

新增图表语义载荷遵循[现有 DOM 契约](./integration/pptx-export-dom-contract.md)，不改写媒体 v1 的既有识别含义。需要不兼容演进时增加版本并保留历史类名兜底；组件公开 API 发生不兼容变化时新增 `.v2` 并联动 manifest 和三端校验。

退出条件：列表可继续编号，卡片可整组移动和拆组，图表数据可在 PowerPoint/WPS 中修改并保存；重新打开后无修复提示，不支持的图表继续保持视觉及准确报告。

### S5 主题和母版

先定义 Runtime 主题色、字体与 PPT 主题槽位的映射，明确哪些颜色保持页面显式值、哪些引用主题槽位。母版仅用于可确认相同的公共背景、页码和装饰，不把页面内容或动态资源错误提升为共享对象。

验收包括主题切换、工作空间字体缺失、不同页面背景、母版编辑和再次保存。字体嵌入、任意 HTML 无损转换、原生视频及完整三维编辑不纳入本轮承诺；现有字体别名映射与视觉降级继续可用。

### 证据口径

1. **Vitest** 验证解析、生命周期和 IR；jsdom 几何回退只属于测试环境能力，不能替代浏览器布局证据。
2. **Chromium** 验证真实文档、视口、动画、资源状态、取消后零下载和 DOM 释放。基础样例可用受控同源页面，发布验收必须包含真实 Runtime 项目。
3. **OOXML** 解包验证页数、文本、段落、合并关系、图元位置、关系文件和备注；增强现有只检查 ZIP、首张条目与体积的 [page-export smoke](../../../tests/e2e/specs/smoke/page-export.spec.ts)。
4. **目标应用** 在固定版本的 PowerPoint 和 WPS 中打开、渲染、编辑、保存并重开，确认无修复提示。替代渲染器结果单独标注，不能据此声明 Office/WPS 已验收。
5. **性能** 固定页面源码、锁文件、浏览器版本、主机和视口，冷缓存和热缓存分开，至少重复十次记录中位数、最慢值、阶段耗时、长任务、可测峰值内存和文件大小。S0 建立基线，S3 实施前冻结具体预算；不预先承诺固定倍数提升。

视觉验收使用统一渲染尺寸、固定字体条件和区域对比，先校准数值容差再冻结阈值。可见文本遗漏、页数错误、层级反转、意外下载和 XML 损坏属于硬失败；抗锯齿和字体差异按固定规则评估，不能靠放宽整页像素阈值掩盖内容错误。

基准和 E2E 证据放入 `test-results/e2e/`。固定样本代码纳入测试，下载的 PPTX、渲染图片、性能临时文件和可再生成大文件不提交。服务已启动时先复用现有测试环境，重置和播种只使用专用测试数据。

| 问题 | 触发与影响 | 修复边界 |
| --- | --- | --- |
