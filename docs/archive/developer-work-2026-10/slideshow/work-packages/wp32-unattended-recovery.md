## 实施记录（2026-10-18）

- 防休眠：新增 `useScreenWakeLock`，只在自动放映的准备/播放阶段持有 Screen Wake Lock；暂停、失败、结束、停止、卸载与控制器销毁立即释放。系统回收 sentinel 后在可见且仍播放时补申请；同一轮自动翻页不重复申请。不可用、`NotAllowedError` 或 `SecurityError` 收敛为 `unsupported`/`denied`，普通放映继续，权限拒绝后不在自动翻页中反复请求。控制条以 `data-wake-lock` 暴露可验证状态，不新增设备权限默认申请。
- 中断恢复：页面 `freeze`、持久化 `pageshow` 和 `visibilitychange` 隐藏均先暂停并释放屏幕锁；重新可见不自动继续，必须显式点击。控制器新增计时迟到守卫（回调晚于截止时间 3s 以上）先暂停，避免系统休眠或长冻结后醒来连跳；旧 generation 回调仍被丢弃。
- 服务与重载恢复：媒体元素处于 `error` 或 `NETWORK_NO_SOURCE` 时，重试播放前先 `load()` 重新选源，本地静态服务恢复后可继续；错误态不自动翻页、不无限重试。浏览器重载从 URL 指定路由重新进入并按项目 `auto_start` 启动。
- 本地放映操作指引：按 WP31 的固定产物与静态服务命令启动并打开入口；系统休眠/窗口隐藏/页面冻结后回到放映窗口，点击控制条继续（不会自动补跳）；本地服务中断时先恢复静态服务，再点击重试；浏览器关闭或崩溃后重新打开同一 URL，按项目 `auto_start` 自动开始或点击开始；结束放映后确认控制条为暂停且屏幕锁释放。权限被拒或设备不支持防休眠时按普通放映操作，不阻断翻页。
- 自动化：`pnpm --dir runtime test` 为 142 files/1105 passed/3 skipped；`pnpm --dir runtime check`、`pnpm --dir runtime build` 与改动文件 ESLint 通过。定向媒体/放映测试 63 passed，覆盖屏幕锁申请/暂停/隐藏/卸载释放、sentinel 回收补申请、拒绝回退、freeze/pageshow 暂停、计时迟到暂停与失败媒体 `load()` 重试。
- 真实浏览器（Windows 10.0.26300 x64，Playwright 1.60.0，有头 Chromium 1280×720，本地静态服务 `127.0.0.1:7416`，构建任务 13）：A1 入场持有屏幕锁；A2 媒体页视频实际播放；A3 暂停释放锁；A4 继续重新持有；A5 隐藏暂停、6s 内不翻页且锁释放；A6 重新可见保持暂停；A7 显式继续；A8 注入 `freeze` 后暂停、8s 内不翻页，A8b 持久化 `pageshow` 保持暂停；A9 继续；A10 关闭缓存并停止本地服务后媒体请求 `net::ERR_CONNECTION_REFUSED`，进入错误态且 2s 内不跳页；A11 重启服务后点击重试恢复媒体播放；A12 浏览器重载从 `#/intro` 自动开始；A13 暂停后锁为 `idle`、媒体全部暂停，播放调度计时句柄清除（活动计时器 3→2，剩余为运行时/界面定时器），`document`/`window` 监听计数保持 14；A15 在权限拒绝上下文（`NotAllowedError`）中仍从开场自动推进到 `/content` 第 2/4 页。控制台仅有 A10 预期的连接拒绝错误。
