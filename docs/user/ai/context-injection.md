# 当前上下文注入

上下文注入是平台让 AI 理解当前创作对象的机制。Backend 会根据用户所在位置和权限，把必要的项目、页面、组件、资源和样式信息组织给 Agent。

## 注入流程

1. 用户在 Editor 中打开工作空间、项目、页面、组件或资源。
2. Editor 在工作空间会话中发起 Run，并携带当前路由候选焦点；Backend 按会话焦点模式固化本轮快照。
3. Backend 校验用户权限。
4. Backend 读取当前范围内的必要上下文。
5. Agent 根据上下文和用户提示词决定回复或工具调用。

## 什么时候注入

打开页面、切换会话、继续 run、发起工具调用前，都可能需要重新读取上下文。平台会尽量避免把无关对象塞进上下文，降低模型误判和成本。

## scope 怎么来

会话以工作空间为稳定授权边界，Run 焦点通常来自当前 UI 路由，也可以固定项目或保持工作空间级。焦点只决定默认理解对象；项目工作集和每次工具权限校验决定实际可操作范围。

## 自动注入哪些内容

- 当前用户和工作空间信息。
- 当前项目、页面或组件摘要。
- 可用资源、主题、样式和字体摘要。
- 固定工具说明，以及模型按需查询后进入消息历史的操作手册。
- 当前会话按显式 workspace/project/page ID 分区的历史消息摘要。
- 本轮焦点、项目工作集、画布尺寸和基础字号。

页面源码、完整项目样式、建议组件和建议资源不会默认注入；内容助手需要时会通过查询工具读取，以减少无关上下文和缓存前缀波动。

## 不会自动注入哪些内容

- 用户无权访问的工作空间或项目。
- Runtime shell 内部实现细节。
- 未被平台披露的工具能力。
- 不必要的大体积文件全文。
- 密钥、凭证和生产环境敏感配置。

## 与上下文隔离的关系

上下文注入以权限和 scope 为边界。AI 不应绕过 Backend 直接读取其他用户、其他工作空间或 Runtime 内部文件。
