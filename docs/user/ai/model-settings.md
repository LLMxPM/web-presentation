# 模型接入与 AI 设置实战

在私有化部署环境下，平台不绑定任何单一商业闭源服务，用户可以使用个人或团队采购的 API Key 自由接入主流大语言模型和图像生成服务。

进入设置：点击右上角用户头像，选择 **"设置与管理"**，在左侧个人设置导航中进入 **"模型连接"**（路径 `/settings/account/models`，旧路径 `/settings/account/ai` 保持兼容）。

---

## 1. 架构理解：聊天模型与图片生成相互独立

在配置前，请务必了解平台的双通道设计：

```
[ 账号 AI 设置 ]
   ├── 聊天模型 (Chat / Text)   ──> 负责对话理解、生成 Vue 代码、分析大纲与工具调用
   └── 图片生成 (Image Gen)    ──> 负责根据提示词生成全新视觉素材并存入资源库
```

- **两套凭证完全隔离**：你在“聊天模型”中填写的 Key 不会自动同步给“图片生成”。即使是同一家服务商（如 OpenAI、阿里云或 OpenRouter），也必须分别在两侧创建供应商并录入各自的连接配置。

---

## 2. 国内主流聊天模型接入指南

聊天模型统一来自 Models.dev 目录：先在「供应商管理」Tab 连接目录内的供应商，再在「模型管理」Tab 用「新建聊天模型」从目录里选模型。模型 ID、上下文上限和能力均由目录决定，页面不再提供手工填写目录外模型 ID 的入口。

> **约束**：只有 Models.dev 目录收录的供应商可以添加聊天模型。自建网关或纯 OpenAI-compatible 端点若未被目录收录，连接本身仍可保存，但暂时无法为其绑定聊天模型；此时可请管理员在页面右上角「刷新规格目录」后重试。

### 2.1 方案 A：DeepSeek 官方 API
DeepSeek 在代码生成与逻辑推理上表现极佳，且成本低廉，是小团队的首选：
- **供应商连接**：在「供应商管理」Tab 选择 Models.dev 目录中的 DeepSeek。
- **Base URL**：默认 `https://api.deepseek.com/v1`（必须带 `/v1`），目录已提供时无需改动。
- **API Key**：填入你在 DeepSeek 开放平台申请的 `sk-xxxxxxxx`。
- **目录中常见模型**：
  - `deepseek-chat`（即 DeepSeek-V3，响应迅速，极度擅长编写页面与组件代码）；
  - `deepseek-reasoner`（即 DeepSeek-R1 深度推理模型，适合处理复杂大纲策划与版式推导）。

### 2.2 方案 B：硅基流动 (SiliconFlow)
国内知名模型聚合托管平台，提供稳定的 DeepSeek 与 Qwen 系列开源模型直连：
- **供应商连接**：优先选择 Models.dev 目录中的 SiliconFlow；目录未收录时只能创建自定义 `OpenAI-compatible` 连接，且暂时无法添加聊天模型。
- **Base URL**：`https://api.siliconflow.cn/v1`。
- **API Key**：填入硅基流动控制台生成的密钥。
- **目录中常见模型**：
  - `deepseek-ai/DeepSeek-V3`
  - `deepseek-ai/DeepSeek-R1`
  - `Qwen/Qwen2.5-72B-Instruct`

### 2.3 方案 C：阿里云百炼 (DashScope)
- **供应商连接**：选择 Models.dev 目录中对应的阿里云/百炼供应商。
- **Base URL**：`https://dashscope.aliyuncs.com/compatible-mode/v1`。
- **目录中常见模型**：`qwen-plus`、`qwen-max`、`qwen-turbo`。

以上模型 ID 只有在当前同步的 Models.dev 目录中存在才会出现在下拉里；目录内容随管理员刷新而变化。

## 3. 独立图片生成服务接入指南

内容助手支持在对话中直接画图并自动存入工作空间资源库。图片服务与聊天完全隔离：在「供应商管理」Tab 点「连接生图供应商」录入凭证，再在「模型管理」Tab 点「新建生图模型」选择模型：

### 3.1 常用生图服务商配置
- **阿里云百炼 (DashScope Image)**：
  - 供应商协议选择 `dashscope_image`；
  - Base URL：`https://dashscope.aliyuncs.com/api/v1`（必须带 HTTPS 与 `/api/v1`）；
  - 常用生图模型：`wanx-v1`（通义万相）。
- **OpenRouter Image**：
  - 供应商协议选择 `openrouter_image`；
  - 常用模型：支持按需调用各类第三方生图模型。
- **OpenAI 兼容生图**：
  - 协议选择 `openai_image`，接入 `dall-e-3` 或兼容生图网关。

> **注意**：如果图片理解和图片生成通道均未配置任何模型，聊天界面中的图片上传入口将置灰禁用。

## 4. 绑定到核心能力槽位

添加完模型之后，在「模型连接」页面的 **「助手配置」** Tab 把它们绑定到平台核心能力槽位：

1. 打开 **「模型连接」** 页面的 **“助手配置”** Tab。
2. **内容生成**：从已添加的聊天模型列表中选择绑定的主模型（如 `deepseek-chat`）。
3. **视觉理解**：选择支持 Vision 视觉能力的模型（如 `deepseek-chat`、`gpt-4o` 或多模态模型）。
4. **图像生成**：选择在生图通道中配置的生图模型（如通义万相或 DALL-E-3）。
5. 点击各槽位右侧的“保存”即时生效。

## 5. 推理设置

### 5.1 推理模式（针对支持 Reasoning 的模型）
- **跟随模型**：默认行为，保持服务商原生逻辑；
- **显式强度**：针对 DeepSeek-R1 等模型，可指定推理强度：
  - `快速 (low)`：压缩思考步数，适合日常轻量修改；
  - `均衡 (medium)`：平衡生成质量与延迟；
  - `深入 (high)` / `极致 (max)`：适合从零规划多页复杂汇报大纲。

### 5.2 上下文与输出边界
- **输入窗口**：每次对话自动使用当前绑定模型的最大输入上下文长度，不需要手动配置。平台内置历史自动压缩机制，确保多轮长会话不超出模型物理上下文。
- **输出上限**：系统统一封顶 32K token，保障长页面代码能够一次性完整生成不截断。
- 推理策略在每次对话发起时根据模型目录（Models.dev）的声明自动确定，并保存到本次对话快照中。

> **注意**：内容助手是工作空间级统一智能体（`agent-coordinator`），不存在隔离子运行或多助手委派。所有工具调用、页面创建和组件管理均在同一个助手会话中完成。

## 6. 独立的高级 AI 个人设置

为了提供更宽裕舒适的配置空间，内容助手的提示词、规范与工具已平铺为个人设置的一级模块：

- **助手提示词 (`/settings/account/prompt`)**：自定义全局系统提示词（System Prompt），调整助手的思考风格与交互行为，支持一键恢复系统内置默认提示词。
- **代码规范 (`/settings/account/code-standards`)**：定义 AI 生成代码时的硬性设计法则，包含页面规范（`page`）与组件规范（`component`），支持 Markdown 即时编辑与一键恢复默认。
- **工具配置 (`/settings/account/tools`)**：查看内容助手的只读契约（JSON Schema、调用范例、返回示例），并可按需开启/禁用特定工具或自定义说明。
